# 安全部署

[返回 README](../README.md) · [升级说明](UPGRADING.md)

首次部署或需要AI协助运维时，先读[上线与日常安全指南](SECURITY-OPERATIONS.md)。本页说明应用机制；该指南逐项说明服务器／网络侧配置、验收、备份与事件处理。漏洞报告见[安全政策](../SECURITY.md)。

## 默认启用的应用防护

应用内防护随 API 启动，不依赖安装 Fail2ban。保护覆盖请求限速、并发与请求体限制、身份验证失败冷却、临时封禁和安全记录；仍需正确部署 HTTPS、可信代理、持久化目录及服务器保护。自动化检查通过不等于不存在未知漏洞，也不能保证抵御所有拒绝服务攻击。

| 项目 | 当前状态 | 边界 |
| --- | --- | --- |
| 初始化与管理员密码 | 一次性安装码；无默认账号；新管理员密码至少15个字符，基础弱口令检查，保存bcrypt | 旧账号不强制改密，旧哈希在成功登录时升级；MD5传输值仍是凭据，须使用HTTPS |
| 管理接口与会话 | 身份／资源编号检查，密码变更撤销旧会话；账号修改和手动封禁需最近五分钟内验证过管理员密码 | 尚无TOTP／Passkey、设备清单或逐设备撤销；并非每项业务操作都要求再次输入密码 |
| 管理员／粉丝登录 | IP／全局速率、验证并发限制，IP与账号维度的失败冷却 | 临时冷却不会永久锁定账号；不能防止已泄露的正确凭据被使用 |
| 签名、领取口令与电子礼物 | 签名流程有IP／UID／全局限额，领取口令与礼物解锁按目标跟踪失败 | 已登录且验证身份的本人领取不靠猜领取口令；B站仍是外部依赖 |
| 投稿、互动、上传及上游调用 | 分类型IP／全局预算与并发；各自的大小／图片校验继续生效 | 不等于磁盘配额、病毒检测或内容审核；应监控空间和上游额度 |
| 实时连接 | 同源／显式来源校验、连接上限、消息大小／频率限制、全局鼠标广播预算、慢连接退出 | 触发资源限制时客户端可能需要重连；不是无限连接容量 |
| 日志与临时封禁 | 有界安全记录、持久化封禁；站点所有者可查看／添加／解除；支持停服本地恢复 | 记录会合并和过期，不是全量请求审计；不收集密码、Cookie、地址等正文 |
| 默认 Nginx 模板 | 安全响应头，API总量100请求/秒、突发200的粗限速 | 精确IP／账号保护在应用中；该总量限制不依赖推测代理后的客户端IP |

### 失败冷却与自动封禁

- 同一来源在一个验证范围内，十分钟累计八次失败，暂停该范围的验证15分钟；重复触发可增加到30分钟、最多一小时。成功验证不会清除该来源对其他账号的失败记录。
- 同一账号或领取目标累计猜错十次（含来自不同IP的分散尝试），短暂冷却30秒；重复触发按60、90秒逐步增加，最多两分钟。管理员以数据库账号ID、粉丝以UID归一化，目标以带密钥摘要保存，不记录原始账号名称或领取口令。
- 持续超限或反复无效请求在两分钟达到30次时，可对该IP的对应接口范围临时封禁五分钟。单次输错或单次无效请求不会导致整站封禁。
- 自动封禁限制对应范围；站点所有者手动封禁则限制该IP的所有Go接口，静态HTML／CSS等不由此管理。IPv4映射地址与IPv6不同写法会规范化，不按整个网段自动封禁。
- IPv6同一 `/64` 另共享对应范围的访问预算，防止不断更换地址制造新身份；这不是整个网段的自动封禁。已经受限的来源不会继续消耗其他来源的全局预算。
- 超限返回真实HTTP 429和 `Retry-After`，不通过等待队列占住业务线程。内存计数达到上限时拒绝新增未跟踪的限额身份，不随意驱逐仍生效的限制。

### 默认资源预算

令牌桶允许短时突发，长期补充速率按分钟计算；下表为每个API实例的默认值，既有业务内部的更细限额仍可继续约束请求。

| 范围 | 每IP每分钟／突发 | 全局每分钟 | 全局请求并发 |
| --- | --- | --- | --- |
| 普通读取 | 600／120 | 12000 | 64 |
| 文件读取 | 600／120 | 12000 | 32 |
| 管理与业务写入 | 120／30 | 1800 | 16 |
| 投稿 | 10／5 | 120 | 4 |
| 表情互动 | 120／20 | 3000 | 16 |
| 上传 | 240／32 | 480 | 4 |
| 管理员验证 | 3／8 | 60 | 2 |
| 粉丝验证 | 3／10 | 120 | 4 |
| 领取凭据 | 12／12 | 300 | 8 |
| 签名与初始化 | 12／12 | 180 | 4 |
| 上游调用 | 30／10 | 120 | 4 |
| 实时连接握手 | 12／12 | 600 | 64 |

每IP请求并发最多为对应范围上限与8的较小值；同一验证目标同时最多进行一次凭据核验。SSE／WebSocket实际连接合计最多256、每IP最多12；WebSocket单条消息最多1024字节，单连接30条/秒、突发40，房间鼠标广播最多30条/秒、突发60，防止随连接数放大转发成本。慢接收端的待发队列有上限，写入超时会断开。

HTTP请求头最多32KiB、读取超时五秒，连接空闲超时一分钟；请求体有路由大小限制、15秒读空闲期限，并在15秒宽限后执行最低4KiB/s的读取进度检查；单次请求总读写上限为15分钟，防止缓慢滴入数据长期占住上传位置。文件传输与普通数据查询使用不同并发预算。

确需调整时，在私有部署配置 `security.guard.policies` 中按上表对应的源码范围名覆盖完整策略，字段为 `per_minute`、`burst`、`global_per_minute`、`concurrent`，例如：

```json
{"security":{"guard":{"policies":{"read":{"per_minute":600,"burst":120,"global_per_minute":12000,"concurrent":64}}}}}
```

范围名见 `internal/guard/guard.go`。所有值须为正数，不能用0关闭防护，修改后重启API。预算不是承载量保证，需结合自己的CPU、网络、用户量和上游额度评估。

### 安全记录、误封与本地恢复

站点所有者在后台「安全」中查看生效封禁和事件、核对当前识别的客户端IP，或手动添加／解除临时封禁。普通管理员无法读取或管理这些记录。手动操作需最近五分钟的密码验证，解除封禁不会关闭正常限速；已有服务器／Fail2ban封禁也不会被本页改变。

状态位于 `state_directory/security/state.json`，默认是 `data/security/state.json`，须持久化并限制访问。最多保存4096个封禁、16384项失败状态及1000组事件；事件按不超过一分钟的窗口合并，最长保留七天，记录的是保留范围内的次数，不是全量请求总数。新封禁同步落盘，一般记录最多约两秒批量保存一次。配置了OSS或MySQL也要保留本地状态目录。

状态文件以原子替换写入，并由操作系统文件锁保证只由一个API实例管理；不要共用状态目录运行多个API。损坏的文件不会被自动当成空状态覆盖。无法保存时，新的验证和写入会受保护性限制；先检查空间、权限或恢复备份。

误封后可以通过服务器本地命令恢复，不需要后台已登录。**先停掉API**，例如原生部署：

```bash
sudo systemctl stop mofufans
sudo -u mofufans /opt/mofufans/mofufans security --state-directory /opt/mofufans/data --unban-ip 192.0.2.1
sudo systemctl start mofufans
```

Docker部署在自己的Compose目录：

```bash
docker compose stop mofufans
docker compose run --rm --no-deps mofufans ./mofufans security --state-directory ./data --unban-ip 192.0.2.1
docker compose up -d
```

将示例IP替换为要解除的真实来源。也可使用 `--unban-id ID` 解除指定封禁；无法确定目标时，`--clear-bans` 可清除应用封禁和失败计数，但保留事件。三种选项只能选一种，API运行时文件锁会拒绝离线修改。文件损坏需先保存故障副本并恢复有效备份，清除封禁命令不修复无效JSON，也不修改业务数据库或服务器防火墙。

参考：[OWASP 认证防护](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[拒绝服务防护](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html)及[安全日志](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)。

## 管理员与会话

新安装没有默认管理员和通用密码。首次设置需服务端生成的一次性安装码，完成后关闭初始化入口。登录仍校验前端 MD5 传输值并在服务端保存为其 bcrypt 哈希；旧 MD5 记录仅兼容登录，成功验证后升级。新建管理员与修改密码使用 `new_password` 提交，在服务端校验长度和基础弱口令；旧前端仅提交 MD5 的改密请求会被拒绝，升级时须前后端同批更新。密码与 MD5 传输值都属于登录凭据，必须使用 HTTPS。

管理员会话有效期为12小时，服务端解码时强制校验有效期，不仅依赖浏览器 Cookie 过期；会话与当前密码绑定，改密后旧会话及近期验证凭据失效。刚完成的管理员登录即可作为最近五分钟内的密码验证。权限在服务端检查，话题、配置、AI测试和私信接口需要对应身份。资源编号不会被请求正文覆盖。浏览器写请求及实时连接校验同源或明确配置的来源，默认不开放跨域；默认仅信任回环代理，其他受控代理来源须显式配置。

公网部署使用HTTPS和Secure Cookie，Go API仅监听本机或受控容器网络。应用已经提供基础限速，反向代理／边缘可以进一步保护；使用CDN时只信任其实际网段，再根据还原的客户端IP限速，不信任任意来源提供的IP请求头。

`server.trusted_proxies` 默认仅含回环地址，不会自动识别 Docker 网桥、面板代理或 CDN。配置时核对整条链路：若代理来源未被正确识别，应用可能把所有访客记为同一个网关 IP，局部限速也会共用预算；若信任非受控代理，访客又可能伪造转发头绕过限制。仅加入实际受控的代理地址／网段，并通过不同来源的普通测试请求核对应用日志中的客户端 IP；配置校验会拒绝 `0.0.0.0/0`、`::/0` 等全地址 CIDR，也不要加入非受控的过宽网段。

## 粉丝身份与收货信息

注册、找回密码和升级验证使用短时一次性签名挑战。UID 是公开标识，不能代替身份验证。用户只能查看自己的地址与寄送／运单记录；管理员操作仍需登录后台。

地址、领取凭据和 B 站登录等敏感字段加密保存。密钥与数据库一并备份，备份也应限制访问。源码、静态导出与 Git 历史不能包含真实名单、地址、Cookie、运行配置或连接资料。

## 私信与外部服务

私信需预览、向所配置的测试 UID 发送并确认。发送账号自动从收件人中排除。队列按管理员隔离，具备总览权限者可查看进度；失败和结果不明分开保留。结果不明时先核对 B 站，避免重复发送。

AI 默认关闭，只有站点所有者能配置和测试。启用图片审核前确认上游适用性，数据范围见 [AI 配置](AI.md)。上游地址由所有者提供，部署者应限制不需要访问的内部网络出口。

## 上传与维护

图片上传校验格式和大小；协作附件与电子礼物按各自的上传规则处理。电子礼物支持分片上传，需预留磁盘空间，并根据实际用途配置上传限制。受限附件经应用核验权限后提供。不要把 `data/` 或上传目录整体映射为公开静态目录。主题图片及桌宠模型由站长提供，使用前确认许可。

应配置日志轮转和磁盘监控，及时安装补丁，并维护可恢复的备份。不要记录密码、Cookie、签名挑战、领取验证码、地址或完整请求体来排查攻击；记录必要的时间、规范化路由、结果、来源与风险原因即可。

## 应用、服务器与网络的分工

应用内限速／封禁可以在请求进入业务处理前拒绝异常访问，减少数据库、密码计算和上游调用的消耗；它不能阻止请求先到达服务器网卡，也不能保护 SSH 或同机其他服务。

Fail2ban 根据日志在服务器或反向代理层封禁来源，可同时保护 SSH 等服务。经过 CDN 的请求需要正确还原真实 IP，单在内核封客户端 IP 未必能拦住由 CDN 转发的 Web 请求。不要因为已内置应用防护就卸载或停用已有服务器保护。

带宽型攻击仍需防火墙、网络服务商或 CDN／DDoS 防护提前处理。应用内防护的合理目标是让基础登录／接口保护随部署默认启用，减少额外组件的配置负担；它不是对整个服务器或所有流量的安全保证。
