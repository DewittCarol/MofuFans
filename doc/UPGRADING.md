# 升级与回退

[返回 README](../README.md) · [安全部署](SECURITY.md)

此版本增加了签名注册、粉丝主页、常用地址、地址簿、发货异常筛选、私信队列监控及安全修复。升级会新增表和字段，应先在数据库副本中演练，再安排正式切换。

应用内默认启用按接口分类的访问预算、失败冷却、临时封禁和有限安全记录，并在 `data/security/` 持久化临时封禁、失败冷却状态与安全记录；速率和并发预算保存在进程内。升级不修改已有业务数据和密码。前后台应与API同批更新：新建／修改管理员密码改用 `new_password` 字段且至少15个字符，旧的仅MD5改密请求会被拒绝；旧账号仍可登录并按原兼容逻辑升级哈希。管理员账号管理与手动封禁操作要求最近五分钟密码验证，参阅[安全说明](SECURITY.md)。

## 升级前

v0.1.1 将鼠标、桌宠和贴表情设置归到「主题管理」，原设置值保持。通用版移除「站点协作」页面及接口，但升级不会删除旧库中的相关表或附件；如需清理，先自行备份并核对用途。

1. 记录当前版本、配置、环境变量及数据目录。停止后台群发，核对仍在发送或结果不明的消息。
2. 完整备份数据库、上传资源、`data/instance.json`、`data/settings.json` 和部署配置。SQLite 运行中使用 backup API 或 `.backup`，不要只拷贝仍有 WAL 的主文件；MySQL 使用一致性逻辑备份。
3. 使用同一份旧密钥启动副本。`security.bilibili_cookie_key` 关联地址、领取凭据、B 站登录和 AI 密钥，不能为了升级重新生成。
4. 核对主题和资源。旧版四模块主题会补入电子礼物模块，既有品牌、颜色和自建预设不被默认主题覆盖。站点素材需由部署者另行保留。

## 切换与检查

停止旧 API 后，同步更新前后台静态产物（或重新构建并切换完整容器镜像），再用原配置和数据目录启动新 API；不要只升级 API 而保留旧版后台。正常启动会初始化新增表和字段。不要为升级开启 `development.skip_database_initialization`，它只适用于已完成定向迁移的环境。

先检查管理员登录、主题、原有提问、名单、礼物、收集批次和包裹。再用测试账号检查签名注册、常用地址和队列预览，不直接启动真实群发。旧管理员登录成功时会把原密码哈希升级为 bcrypt，旧会话需要重新登录。

地址簿记录历史地址，每个 UID 至多一个常用地址。旧地址不会因为升级自动获得长期使用授权；自动填写取决于用户授权或主播已确认的托管设置。取消后不撤销已登记批次和已寄包裹的地址快照。

旧版通用站通常已有独立收集批次。更早的定制结构、正在使用的合并发货字段或非标准手工改库，需先定向迁移。`internal/database/feature_parity.go` 包含旧结构的迁移与校验逻辑，应由维护者根据数据库副本的演练结果选择使用。

## 回退

代码回退与数据恢复分开处理。升级后已有新投稿、地址或发送结果时，不要用旧整库覆盖。先停写并备份当前状态，再确认旧代码兼容性；不兼容时应发布修复版本或编写定向转换。副本验证不能替代正式切换后的核对。

仓库测试使用合成 SQLite 数据和模拟上游，不代表真实 MySQL 升级、真实 OSS 凭据、B 站实时签名与私信风控或每家 AI 服务均已实测。
